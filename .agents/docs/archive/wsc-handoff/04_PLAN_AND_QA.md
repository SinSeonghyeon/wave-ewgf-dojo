# 제작 플랜과 검수

이 계획은 제작 순서와 합격 조건이다. 기존 시안의 색·배치·모션 곡선을 재현하라는 설계도가 아니다.

## 1단계 — 인수 / 데이터 대조

- [ ] 패키지 읽기. 고정 요구와 미확인 주장을 분리해 작업 노트에 기록.
- [ ] 원본 경로/동봉 파일 확인. 별도 세션 전용 `.sandbox/wsc-<session-id>/` 또는 독립 작업 폴더 생성. 다른 세션 결과 덮어쓰기 금지.
- [ ] 실제 플레이 재생/프레임 확인, 후보의 결과 분류. 120fps를 게임 120f로 환산하지 않음.
- [ ] 누락 소재 목록 작성: 실전 활용, 대안 세 종류, 개별 조건 증명, 중복 없는 실패 16개. 부족한 곳은 더미로 진행.
- [ ] 역사 문구는 최종 녹음 전 검증. 이 패키지 작성 시 새 웹 검증을 했다고 주장하지 않음.

## 2단계 — 독립 연출 설계

- [ ] 한 가지 일관된 아트/편집 방향을 제시. 프레젠테이션이 아닌 영상의 시간 흐름으로 설계.
- [ ] 대본 읽기 테스트 후 예상 길이 산정. 임의의 90초/2분 목표를 위해 말을 과속하지 않음.
- [ ] 장면표에 대사 / 화면의 목적 / 실제 소재 또는 더미 ID / 모션 / 사운드 / 검증 상태를 기록.
- [ ] 첫 검토용으로 도입~실패 연결 20~40초와 7→8→9 프레임 설명 짧은 구간 제작. 캐릭터는 내레이터만. 검토용이라는 점 명시.
- [ ] 사용자 피드백 후 본편 전체 편집. 자동 진행 모드 요청 시 중간 승인 대기 대신 핵심 샘플을 검수하고 가정·미확인 사항을 보고하며 러프컷까지 진행.

## 3단계 — 본편 러프컷

- [ ] 플레이 동작 → 입력 확대 → 도식이 끊기지 않게 연결.
- [ ] 실패 몽타주 1/2/4/8/16의 증가가 읽히게 구성. 내레이션과 원본 게임 오디오 간섭을 피함.
- [ ] ↓/↓↙←/↙ 비교는 원본 로그와 동일 기준으로 표시. 수치 누락은 '측정 대기'.
- [ ] 한국어 TTS·자막 싱크. RP 발음은 알피로 발음 사전만 분리, 자막은 RP 유지. ↘ 등의 기호를 TTS에 그대로 읽히지 않게 말하기 텍스트 분리.
- [ ] 더미 교체가 파일/데이터 교체만으로 가능하게 구성. 화면 속 상수에 미측정 값을 숨겨 넣지 않음.

## 4단계 — 증거 확정 / 최종 편집

- [ ] A/B 기점과 첫 프레임 포함 규칙, 9+2 개별 근거를 확인. 사용자 규칙과 개별 촬영 검증을 구별.
- [ ] 세 대안과 기준 방식 총 4행의 정확한 수치를 기록. 출처/클립/시작 프레임/종료 프레임을 추적 가능하게.
- [ ] ↓ 8f 주장과 7f 이하 횡이동 관찰 재대조. 포함 규칙 때문에 1f 오차가 생기는지 확인.
- [ ] '실전 유용'을 보여줄 실제 장면 확보. '시간이 비슷함'을 모든 성능이 같음으로 확대하지 않음.
- [ ] 역사 진술 및 캐릭터 권리 확인. 타인 자료 직접 재사용은 별도 확인.
- [ ] 미확인 항목이 남으면 최종본이라 부르지 말고 검토본과 남은 목록을 납품.

## 5단계 — 쇼츠 / 납품

- [ ] 본편 내용을 단순 세로 자르기 하지 않고 9:16로 재배치. 짧은 정의 → 필요한 조건 → 결론 중 집중할 하나의 흐름으로 압축. 핵심 조건을 생략해 오해를 만들지 않음.
- [ ] 본편/쇼츠 MP4, 자막 SRT, 대사 원본, 음성, 편집 가능한 소스, 소재 목록, 렌더 명령/환경, 검증 결과를 전달.
- [ ] 가능하면 자막 없는 클린 영상도 분리. 업로드/게시/외부 서비스 유료 사용은 별도 허가 없이 하지 않음.

## 품질 체크

내용: RP 7→8→9 순서 / 허용폭 1, 1–2, 1–3 / 8+1 추천 파트 없음 / 내레이터 캐릭터 / 비교 4행 / 허위 수치 없음 / 증거 없는 최초 발견 주장 없음.

시각: 고정 타이틀/페이지 번호 없음 / 모든 주요 커맨드 화살표+★ / 입력과 프레임축 중복 없음 / 정지화면으로 TTS 시간 채우기 없음 / 폰에서 프레임 숫자와 자막 판독 가능 / UI 안전영역 검토.

기술: 전체 디코딩 오류 없음 / 시작·중간·끝 탐색 및 재생 / 오디오 잘림·클리핑·과도한 말속도 청취 / 자막 넘침·누락 / 검토 영상의 더미 표시 / 기존 원본 불변.

도구 한계: 직접 본 장면과 메타데이터만 확인한 것을 구분해서 보고. TTS 청취가 불가능하면 음성 품질을 검증했다고 말하지 않는다. 파일 생성만으로 영상 완성 선언 금지.

동일 저장소에서 코드를 바꿨다면 상위 규칙에 따른 단위 테스트 → 브라우저 스모크. 문서/데이터만 인수하는 단계에서는 JSON·링크·소재·요구사항 대조를 수행하고 앱 테스트를 돌렸다고 주장하지 않는다.
