## 측정 정의

- A: ↘ 입력 기준부터 ←까지 프레임 간격. B: ←부터 RP까지 간격.
- A+B는 '↘부터 RP까지 상대 입력 간격'이지 전체 커맨드 시작부터 타격까지가 아니다. 기술 발생 시간과도 다르다.
- 첫 프레임 포함 여부 및 각 입력 유지/중간 방향은 원본 기록으로 대조 필요. 0f는 설명용 기준점.
- 영상 컨테이너는 120fps, 게임 화면의 FPS는 약 60. 영상 프레임을 그대로 게임 판정 프레임으로 세지 않는다. 편집 출력 fps 역시 별개다.
- 메모의 '왼손'은 사용자 정정에 따라 RP. 불명확한 '13발동 x', '8+2왼손 이후 오른손', '2+1+6 +3' 등은 임의 정규화하지 않고 원문에 남긴다. 중복 기록 횟수를 시도 횟수로 취급하지 않는다.

## 근거 수준

1. `memo_explicit`: 메모에 성공/실패가 명시. 원본 영상의 특정 시도와 연결된 것은 아님.
2. `user_rule_only`: 사용자가 확인했다고 한 전체 규칙. 9+2는 개별 메모 행 없음.
3. `user_report_pending_capture`: 대화에서 추가된 비교 실험 관찰. 수치/로그/영상 대조 미완료.
4. `prior_visual_candidate`: 이전 원본 검토에서 찾은 후보. 원본을 다시 확인하고 정확한 인/아웃을 잡을 것.
5. `dummy`: 편집 자리표시자. 공개 증거로 사용 금지.

## 대안 비교 — 아직 비어 있는 것

- ↓ 유지: 사용자 보고로 7f까지 횡이동, 8f 이상 유지 후 떼고 RP. `down_hold_user_report_f=8`만 존재. 전체 타격 시간은 미측정.
- ↓↙← 및 ↙: '웨이브 캔슬과 시간 차이가 크지 않다'는 사용자 관찰은 있지만 수치는 전달되지 않음.
- 공정 비교는 시작 자세·이동 상태·거리·캐릭터·게임 빌드·입력 시작 프레임·기술 시작 프레임·타격 프레임을 기록한 뒤 진행.
- 권장 표는 입력 준비 구간과 전체 소요 구간을 분리. 기상 RP 자체의 발생만 비교하면 입력 비용이 사라짐. A+B와 전체 소요를 같은 열에 넣지 않는다.
- 최소 관찰값과 반복 재현성은 별도. 한 번의 최단 입력을 일반적인 성공률이라고 말하지 않는다.
- 사용자에게 게임 상세 버전은 필수 요청하지 않았음. 공개 전 가능하면 촬영 날짜/보이는 빌드를 기록하되 빌드 미상으로 시안 작업을 중단하지 않는다.

## 더미 사용법

- 실패 몽타주 16개는 `montage_slots`로 제공. 실제 시간/영상은 모두 null. placeholder 카드 또는 추상적인 재생 영역을 만들 수 있다. 모든 검토 출력에 '임시 영상 / 교체 예정' 등 식별 표시.
- 실제로 확인된 서로 다른 시도를 찾은 슬롯만 `asset_id`, 인/아웃, `unique_attempt_id`로 채운다. 같은 시도를 복제해 채우지 않는다.
- 비교 4행의 전체 시간은 모두 null. 표시값은 '측정 대기'. 막대 그래프가 필요하면 숫자 비교가 아닌 동일 길이 자리표시자로만 검토하며 더미 표시.
- 실패 영상 부족, 실전 장면 부족, 대안 입력 영상 부족은 자리표시자로 연결해 편집 검토를 계속할 수 있다.
- 최종 공개용 빌드는 dummy, null 비교 수치, 미확정 역사 문구, 미확인 권리가 남으면 경고/실패하도록 설계. 모든 편집 진척을 멈출 필요는 없고 '최종' 승격만 막는다.
