# 다른 세션에 넘길 프롬프트

아래 프롬프트와 패키지 ZIP을 전달한다. 동일 PC라면 ZIP 대신 패키지 폴더 경로를 주면 된다. 이전 시안은 첨부하지 않는다. 모델별 비교를 원하면 같은 패키지와 같은 작업 범위를 사용한다.

## 기본 프롬프트 — 기획과 핵심 구간부터

```text
철권 8 '웨캔기어' 유튜브 영상을 제작해줘. 제공한 제작 패키지가 현재까지 합의된 요구사항이다.

인계 브랜치는 SinSeonghyeon/workspace02다. 같은 PC에서는 아래 ZIP을 네 별도 작업 폴더에 복사해서 풀고 사용해줘:
C:\Users\gus54\Videos\WSC-Production-Handoff\2026-09-17\wsc-production-handoff.zip
공유 ZIP은 수정하지 마. 동시 작업이면 인계 커밋에서 별도 브랜치·워크트리를 사용하고, 기존 워크트리나 변경을 강제로 초기화하지 마.

먼저 00_START_HERE.md에 적힌 순서로 브리프, 통합 대본, 데이터/소재, 제작 플랜을 읽어줘. 동일 PC의 문서 경로는:
C:\Users\gus54\orca\workspaces\dojo\workspace02\.agents\docs\wsc-handoff
다른 환경에서는 첨부 ZIP을 풀어서 사용해줘. 캐릭터 원본과 프레임 메모는 ZIP assets에 있으며, 원본 플레이 영상은 별도 전달이거나 data.json의 로컬 경로에 있다.

이번에는 다른 모델의 독립적인 편집 방향을 보고 싶다. 기존 .sandbox/wsc-video/의 HTML, 코드, 영상, 스크린샷과 과거 VIDEO_WSC.md를 열거나 재사용하지 마. 기존 시안이 있는지 검색해서 따라 하지도 마. 원본 촬영본과 원본 캐릭터 이미지는 사용해도 된다.

내용과 데이터 정확성은 지키되 디자인, 색, 폰트, 모션, 장면 연결과 제작 도구는 새로 설계해줘. PPT나 교육 슬라이드처럼 만들지 말고, 담담한 다큐 패러디 톤의 실제 유튜브 영상으로 만들어줘. 캐릭터는 연구원이나 주인공이 아니라 내레이션을 전달하는 역할만 맡긴다.

최신 변경을 특히 지켜줘:
- RP 설명은 뒤 7 → 8 → 9 순서. 허용폭은 각각 1 / 1~2 / 1~3프레임.
- 8+1을 추천하는 별도 연습 파트는 없다.
- 기본 커맨드를 먼저 설명하고 '설명만 들으면 간단해 보입니다. 직접 해보기 전까지는요.'로 실패에 연결.
- 실패 몽타주는 1 → 2 → 4 → 8 → 16. 더미를 실제 다른 시도인 것처럼 꾸미지 말 것.
- 후반은 실전 유용성 → 어려운 캔슬이 필요한가 → 세 대안과 비교 → 사용자 의도에 맞는, 근거 범위 안의 결론.

data.json의 null은 모르는 값이지 0이 아니다. 미측정 수치를 날조하지 마. 영상이 없으면 명확히 더미 표시를 하고 교체 가능한 구조로 진행해줘. 전체 제작을 멈추지는 말되, 검증되지 않은 내용이 있는 결과물은 최종 공개본이라고 부르지 마.

우선 네가 이해한 핵심 요구와 누락 소재를 짧게 정리하고, 하나의 독립적인 연출 방향 및 장면별 플랜을 제시한 뒤 실제 핵심 구간을 제작해줘. 도입~실패 연결 20~40초와 7→8→9 프레임 설명 샘플을 우선 보고 싶다. 샘플을 보고 피드백한 다음 본편과 쇼츠로 확장하자. 계획만 말하고 끝내지 말고 재생 가능한 결과물을 만들어줘.

별도 작업 폴더를 만들고 원본·기존 결과물을 덮어쓰지 마. 프로젝트 앱은 수정하지 마. 커밋·푸시·유튜브 업로드·외부 유료 서비스 사용은 별도 요청 없이 하지 마. 실행하지 못한 도구나 보지 못한 영상을 봤다고 말하지 마.

결과에는 재생 파일/미리보기, 수정 가능한 소스, 사용 소재와 더미 목록, 실행/검증 방법을 포함해줘.
```

## 처음부터 전체 러프컷까지 맡길 때

위 프롬프트의 '우선 네가 이해한…' 문단만 아래로 교체한다.

```text
우선 핵심 요구와 누락 소재, 독립적인 연출 방향 및 플랜을 짧게 정리한 뒤, 별도 승인 대기 없이 본편 전체 러프컷과 쇼츠 러프컷까지 만들어줘. 내부적으로 핵심 구간을 먼저 렌더링하고 검수한 다음 확장해줘. 부족한 자료는 명확한 더미로 처리하며 가정과 미확인 사항을 보고해줘. 최종 게시용 확정이나 업로드까지 요청하는 것은 아니다. 러프컷은 재생 가능한 MP4로 제공해줘.
```

## 파일 접근이 없는 채팅 모델에 맡길 때

ZIP과 원본을 첨부한 뒤 실제로 파일 읽기/코드 실행/영상 렌더가 가능한지 먼저 확인한다. 렌더 기능이 없다면 납품 범위를 대본·장면표·모션 명세·실행 가능한 제작 코드로 명시한다. 존재하지 않는 MP4 링크를 만들게 하지 않는다.
