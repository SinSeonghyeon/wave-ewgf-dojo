# 웨캔기어 연습 기능 — 확정 설계

작성: 2026-09-17. 확정: 2026-09-18. 상태: **사용자 판정·범위 승인 / 구현 및 자동 검증 완료, 사용자 조작 확인 대기**.

아래 설계는 2026-09-18 사용자 답변으로 확정했다. A 표시는 8·9·10f이며, 최종 정정에 따라 대각 자체를 1f로 센다. 따라서 실제 경과는 7·8·9f다. 10~12절이 최종 결정이다. 11절의 후속 UI 요청으로 최초 3단계 구성을 통합 평가 + 로컬 도전으로 변경했다.

이 문서는 영상 제작이 아닌 미시마 도장 사이트의 연습 기능 제안이다. '실험 규칙'은 사용자가 전달한 결과이며, 에이전트가 게임을 실측한 자료는 아니다. 최초 제안 구조를 유지하되 확정 내용과 구현 검증을 반영했다.

## 1. 무엇을 연습하는가

웨캔기어는 '웨이브 캔슬 기상 어퍼'의 줄임말이다. 웨이브 도중 뒤 입력으로 캔슬하고 RP를 입력하는 타이밍을 연습한다.

1P 방향의 개념적 입력 순서: `→ ★ ↓ ↘ … ← … RP`.

- 숫자 표기: `6 N 2 3 … 4 … RP`. 방향 2와 공격 버튼 2(RP)는 구별한다.
- ★는 중립. 화면의 주 표기는 화살표 + ★ + RP로 제안한다.
- 2P에서는 앞/뒤 및 대각 방향을 반전한다. ↓와 ★는 그대로다.
- `…`는 간격을 뜻하며, ↘나 ←를 계속 유지해야 한다는 뜻은 아니다. 허용 방향은 10절에서 확정했다.
- 이번 범위는 사용자 철권8 기상 RP 실험에서 얻은 조건이다. 모든 캐릭터·기상 기술·게임 버전에 통용된다고 홍보하지 않는다. 사이트에는 공식 캐릭터 이름·이미지·게임 음원을 추가하지 않는다.

목표는 성공 여부뿐 아니라 **뒤 입력이 어긋났는지, RP가 어긋났는지** 즉시 알아보게 하는 것이다. 실제 게임 전체를 재현하는 시뮬레이터는 아니다.

## 2. 판정의 근거와 두 구간

근거: 사용자의 프레임 실험 메모 및 후속 정정, 기존 인계 자료 `wsc-handoff/data.json`의 `rule`과 `tests`. 메모의 '왼손'은 후속 정정에 따라 RP로 취급한다.

| 구간 | 의미 | 성공 조건 |
|---|---|---|
| A | 웨이브의 ↘ 입력 기준 → 뒤 입력 | 8·9·10f |
| B | 뒤 입력 → RP | A에 따라 아래처럼 달라짐 |

| A: 뒤 입력 시점 | B: RP 허용 간격 | 성공 조합 |
|---|---|---|
| 8f | 1f | 8+1 |
| 9f | 1~2f | 9+1, 9+2 |
| 10f | 1~3f | 10+1, 10+2, 10+3 |

중요한 구별:

- '8~10f 뒤 입력 + 1~3f RP면 전부 성공'이 아니다. 8+2와 9+3은 실패다.
- A는 최초 →부터 재지 않는다. ↘ 기준이다. ↘ 입력 프레임은 1이고, 실제 7·8·9f가 경과하면 A=8·9·10f로 센다.
- A+B는 상대 입력 간격이다. 기술 발동 속도나 타격까지 걸린 전체 시간이 아니다.
- 10+2는 사용자가 확인한 전체 규칙에는 포함되지만 원본 메모의 개별 성공 행은 없다. 구현 테스트에는 넣되 근거 수준을 혼동하지 않는다.
- 풍신권 또는 선 자세 기술이 나오는 실패 외형은 관찰했지만, 각 A/B와 어떤 실패 기술이 대응하는지는 미확정이다.

## 3. 첫 버전 범위 제안

**별도 '웨캔기어 연습' 모드**를 추가한다. 제한 시간 없는 반복 연습으로 시작한다.

- 모든 모드에서 동일 커맨드로 웨캔기어·초풍·나락·통발 등을 쓸 수 있다(후속 사용자 요청). 모드는 평가·집계 대상과 화면을 선택한다.
- 키보드·게임패드·터치 및 1P/2P를 기존 입력 경로로 지원한다.
- 별도 단계 버튼 없이 전체 입력을 항상 평가한다. 하단 평가 패널에서 A·B를 따로 보여준다.
- 웨캔기어 전용 현재 세션 통계를 표시한다. 새로고침 뒤 기록 보존은 첫 버전에서 제외한다.
- 순위 등록, 업적, 공유 카드 확장, 서버·DB 변경은 제외한다. 후속 요청으로 로컬 랜덤 과제 10회 도전을 추가했다.
- ↓ 유지, ↓↙←, ↙ 유지 방식의 기상어퍼는 이번 판정 대상이 아니다.
- 영상용 수염 캐릭터는 넣지 않는다. 사이트의 기존 자체 SD 캐릭터를 사용한다.

이 범위는 사용자 승인 완료(2026-09-17~18).

## 4. 연습 흐름과 화면 (후속 요청 반영)

- 왼쪽은 기존 자체 캐릭터 스테이지, 아래는 `6N23 · 뒤 · RP` 안내와 프레임 표. 선행 웨이브는 `6N23` 한 덩어리로 표시하며 그 구간의 프레임·발동 시간을 표시하거나 점수화하지 않는다. 프레임 표는 마지막 유효 대각을 1f로 시작한다.
- 플레이 아래는 웨캔기어 타임라인·평가 패널. 단계 선택 없이 전체 커맨드를 입력하면 성공·실패와 A(뒤 타이밍)/B(RP 연결)를 두 칸에 동시에 표시한다. 각 칸에는 정수 f, 목표 범위, 원시 소수 f·ms가 나온다.
- 뒤 허용 구간은 실선, RP 허용 구간은 점선으로 표시한다. 없는 B는 '—'이며 0f로 오해시키지 않는다. 중간 입력과 RP가 같은 시간 축에 남는다. 15f를 넘은 입력은 축에서 제외하되 상세 수치와 판정은 유지한다.
- 세션 통계는 하나(시도·성공률·현재/최고 연속·중단). 최근 기록과 판정 안내는 접이식이다. 모바일은 오른쪽 패널이 아래로 내려오고 프레임 표만 가로 스크롤한다.
- **랜덤 과제 10회 도전:** 1P/2P 옆 시작 버튼 → 3초 카운트다운 → 과제 10개 평가. 매 과제 N=0~3를 균등 무작위로 선택하며 중복을 허용한다. `웨이브 N회 후 웨캔기어`는 정확히 N+1번째 웨이브의 대각에서 웨캔기어에 성공해야 정답이다(N=0은 첫 번째, N=3은 네 번째). 하단 평가에 요구/현재 횟수를 표시하고 결과에도 목표/실제 횟수를 남긴다. A/B 판정은 유지하며 횟수 불일치는 도전 실패로 집계한다. 웨캔기어로 완료한 버튼 입력은 성공·실패 모두 다음 과제로 진행하고, 선행 오류·1초 중단은 분모 제외 및 같은 과제를 처음부터 재시도한다. 유효한 캔슬 6 → N → 별도 시작 6 → (N) → 2 → 3만 연속 횟수를 늘린다. 도전 집계와 전체 WSC 세션은 별도로 유지하되 과제 실패는 양쪽 WSC 집계에 반영한다. 10회 후 성공률/최고 연속 표시, 이후는 자유 연습이며 완료 결과는 다음 도전까지 보존한다. 완주 결과는 전용 리더보드에 등록한다(2026-09-19). 기존 로컬 기록·등급·공유는 추가하지 않는다.
- 도전 취소 버튼 및 모드/방향/모달/포커스/탭 숨김 전환은 진행 시도와 도전을 취소한다. 세션 초기화 버튼은 제거했다. 새로고침하면 둘 다 사라진다.
- 성공 연출은 앉기 → 짧게 전진하며 기상어퍼 → 복귀. 자체 캐릭터·기술명 팝, 사거리 안의 일반 더미만 반응한다. `attempt`·`strike`·`rushStrike`나 기술 통계/업적을 호출하지 않는다. 실패 기술은 단정하지 않는다. 새 소리는 없고 연출 끄기/동작 줄이기면 정적 피드백이다.

## 5. 브라우저 프레임 환산 — 승인 완료

게임 실험은 정수 프레임이지만 브라우저는 밀리초 입력 시각을 받는다. 정수 프레임을 아래 승인된 실수 구간으로 환산한다. 화면 주사율이나 애니메이션 콜백 횟수로 프레임을 세지 않는다.

웨캔기어는 승인된 **60Hz 기준 간격 반올림 방식**이다.

```text
FRAME = 1000 / 60 ms
aRaw = (tBack - tDF) / FRAME
bRaw = (tRP - tBack) / FRAME
A = floor(aRaw + 0.5) + 1  # 대각 입력 프레임을 포함
B = floor(bRaw + 0.5)
성공 = 유효한 선행 입력 AND A ∈ {8,9,10} AND 1 ≤ B ≤ A−7
```

예를 들어 A=8의 실제 경과 구간은 [6.5, 7.5)f가 된다. B=1의 경과 구간은 [0.5, 1.5)f다. 이것은 **브라우저 연습용 근사 정책**이지 실게임 내부 판정의 확인된 재현이 아니다. 두 간격을 각각 반올림하는 것과 게임의 공통 프레임 격자에 입력을 배치하는 것은 경계에서 결과가 다를 수 있다.

- 사용자 승인: A는 대각 입력 프레임 1, B는 뒤 입력 프레임 0. 동일 시각 뒤+RP는 실패.
- raw ms와 소수 프레임을 보존하고, 주 표시에는 판정에 사용한 정수 프레임, 상세에는 실측 소수값을 표시한다.
- 초풍은 별도 승인에 따라 공통 60Hz 격자에 **각 입력 시각을** 반올림해 같은 칸인지 비교한다. 웨캔기어의 간격 반올림과 다르다. 옛 판정 폭 선택 UI는 제거했다.
- 같은 시각의 뒤+RP는 B=0으로 별도 처리하며, 우연히 이벤트가 호출된 순서 때문에 B=1 성공으로 바꾸지 않는다.
- 키보드·패드·터치의 샘플링 차이와 게임과의 오차를 안내한다. 하드웨어 정밀도를 검증했다고 주장하지 않는다.

## 6. 시도와 실패 처리 제안

한 번의 선행 커맨드에서 결과는 최대 한 번만 낸다. 새 선행 커맨드는 새 기준점을 만든다.

| 상황 | 안내 / 집계 제안 |
|---|---|
| RP 입력 완료 | 전체 결과 1회, A·B 동시 피드백 |
| 뒤 입력이 빠르거나 늦음 | A 실패; 특정 게임 기술 이름은 붙이지 않음 |
| 유효한 A, RP가 허용 폭 밖 | B 빠름/늦음 |
| 뒤 없이 RP | '뒤 입력 누락', 시작된 시도가 있으면 실패 1회 |
| 잘못된 공격 버튼 | 'RP를 입력하세요', 시작된 시도는 실패 1회 |
| 커맨드 순서 오류 | 구체적인 누락/순서 안내, 완성 시도와 별도 표시 |
| 기준 ↘ 이후 입력을 멈춤 | 대기 만료 후 '입력 중단'; 성공률에서는 제외, 별도 중단 수 |
| 아무 커맨드 없이 버튼만 누름 | 안내만; 실패를 무한 누적하지 않음 |
| 모드/방향 전환, 탭 숨김, 포커스 상실, 모달 열림 | 진행 중 시도 취소; 실패로 누적하지 않음 |

대기 만료는 UX 정책이다. 확정값은 마지막 관련 입력 후 1초이며, 게임의 유효 시간으로 소개하지 않는다. 타이밍 유효 범위를 이미 지나도 즉시 입력을 버리지 않고, 만료 전 RP가 들어오면 늦은 수치를 보여준다. 키 자동 반복이나 눌러 둔 RP는 새 시도를 만들지 않는다.

## 7. 기존 기능과의 분리

현재 코드 확인 사항: `onDir`의 기존 `cd` 흐름은 뒤 입력에서 초기화될 수 있고, `onButton`의 RP는 기본적으로 초풍 `attempt()` 경로를 탄다. **기존 초풍 실패 이름만 바꾸어서는 구현할 수 없다.**

구현 방향:

- 전용 `wsc` 상태에 선행 입력, 기준 ↘ 시각, 뒤 시각, 완료 여부를 보관한다.
- 입력 소스 정규화·1P/2P 변환은 기존 공통 경로를 사용한다. 전용 모드에서 판정·결과의 소유권을 분명히 해 중복 호출을 막는다.
- 기존 `completeCD()` 등 입력 인식·연출은 모든 모드에서 공유한다. `completeCD/attempt/strike/addLog`의 기존 통계·업적 쓰기는 wsc 모드에서 막는다. 뒤 입력이 있는 WSC 후보는 버튼 입력을 먼저 소비해 기존 초풍 attempt와 중복 판정하지 않는다.
- 웨캔기어 성공/실패는 초풍 시도·성공률·히스토그램·연속 초풍·기존 측정 점수·기술 업적에 들어가지 않는다. 전용 모드에서의 웨이브도 첫 버전에서는 기존 누적 통계에 더하지 않는다.
- 전용 모드에서 기존 순위·공유 버튼이 잘못된 보드에 등록하거나 과거 모드 통계를 공유하지 않게 한다.
- 새 문자열은 ko/en/ja I18N, 색은 기존 :root 토큰, 그림은 자체 리소스. 외부 라이브러리·엔드포인트 추가 없음.
- 저장·초기화는 전용 세션 데이터 경계를 지키고 기존 사용자 기록을 지우지 않는다.

## 8. 구현 후 검증 계획

1. 순수 조합 판정: 성공 8+1 / 9+1 / 9+2 / 10+1 / 10+2 / 10+3. 실패 7+1 / 7+2 / 8+2 / 8+3 / 8+4 / 9+3 / 11+1 / 11+2 / 12+4. 추가 경계 테스트 B=0·음수·누락·10+4는 정책 테스트로 분리해 게임 실측이라고 부르지 않는다.
2. 승인된 시간 환산의 각 경계 직전·정확한 경계·직후, 동일 시각 이벤트, 화면 60/120Hz와 무관한 결과를 검증한다.
3. 선행 입력 누락, 새 ↘ 기준점, 연속 웨이브, 뒤 유지/중립 조건, 중복 RP, 다른 버튼, 대기 만료를 테스트한다. 허용 경로는 10절을 기준으로 검증한다.
4. 1P/2P, 세 입력 장치, 모달/포커스/모드 전환 시 취소, 언어 전환 후 동적 결과를 검증한다.

## 10. 사용자 확정 조건 (2026-09-18)

1. **A 포함 기준(최종 사용자 정정):** 대각 입력 순간을 **1f**로 센다. 뒤 입력은 여전히 A=8·9·10이며 실제 경과는 **7·8·9f**다. `A=round((tBack−tDF)/FRAME)+1`. A=8이면 B=1, A=9이면 B=1~2, A=10이면 B=1~3. B는 뒤 입력 순간을 0으로 세는 기존 기준 유지.
2. **A 중간 방향:** 대각 유지, 중립, 진행 방향(앞) 입력 1회를 허용한다. 앞이 2회 이상이거나 그 외 방향이면 기존 후보는 무효. 다만 완전한 다음 웨이브(캔슬 앞 → 중립 → 별도 시작 앞 → (중립) → 아래 → 대각)가 완성되면 새 후보를 만들고 마지막 유효 대각으로 기준점을 교체한다. 취소 앞을 새 시작 앞으로 겸용하지 않는다.
3. **B 중간 방향:** 뒤 유지 또는 중립에서 RP. 다른 방향은 실패. 뒤+RP 동시는 B=0 실패. 뒤 입력 프레임을 0으로 두고 다음 1f부터 RP 허용.
4. **선행 입력:** `6N23`과 `623` 모두 허용. 기존 웨이브에도 중립 생략 허용(기존 코드에 이미 있어 회귀 테스트와 안내를 추가). 선행 순서 오류는 완성 시도 분모와 별도 표시.
5. **브라우저 환산:** WSC는 시간 간격을 각각 `floor(ms / (1000/60) + 0.5)`로 반올림하고 A에만 1을 더한다. 원시 ms·소수 f 보존. 시도 대기는 마지막 관련 입력 후 1초이며 중단은 분모 제외, UI 취소는 기록하지 않는다.
6. **추가 승인된 초풍 변경:** `frameSlot(t)=floor(t / (1000/60)+0.5)`로 각 입력을 공통 칸에 놓고 `frameSlot(tRP)===frameSlot(tDF)`일 때만 성공. 공통 원점은 브라우저 monotonic timestamp의 0(`performance.timeOrigin`). RAF 횟수와 화면 주사율을 쓰지 않는다. 음수 오프셋 pending도 동일 규칙. 기존 0.5/0.7/0.9f 선택 제거, 공유 카드·히스토그램·소개 갱신.
7. **기존 데이터 호환:** 서버·DB 변경 없음. 옛 `store.window`·Worker `win` 형식은 유지하되 새 초풍 판정에는 쓰지 않는다. 순위의 옛 판정 폭 열은 새 규칙으로 오해하지 않게 제거. 기존 점수·기록·업적은 지우지 않는다. 0.5f 선택이 사라져 사범 피부의 새 진행은 동일 프레임 성공 중 원시 간격 ±8ms 이내를 세며 이전 진행·획득은 유지한다. 나락의 기존 선입력 완충은 그대로 둔다.

실패 결과는 입력 구간·순서 오류만 설명한다. 실제 게임 실패 기술과 A/B의 대응은 확인하지 않았으므로 기술명을 단정하지 않는다.

## 12. 공통 커맨드·실시간 표시 (2026-09-18 사용자 후속 요청)

- 자유 연습과 모든 측정 모드에서도 웨캔기어를 사용한다. wsc 모드에서도 초풍·나락·통발·이동 연출을 기존 커맨드로 쓴다. 대각 후보의 뒤 입력이 있는 경우만 웨캔기어로 평가하고, 뒤 없이 RP를 누르면 기존 초풍 판정이다. 다른 기술 입력은 후보를 정리하되 도전 과제·횟수를 소비하지 않는다.
- 기술 인식과 기록을 분리한다. wsc 모드에서 수행한 일반 기술도 기존 누적 통계·업적에 넣지 않는다. 다른 모드의 선행 웨이브는 기존 규칙대로 점수화하되 웨캔기어 마무리 성공·실패는 초풍 시도·측정 점수·업적에 넣지 않는다. 서버·DB 변경 없음.
- 하단 #inputs의 입력 간격 프레임 이력을 복구하고 일반 기술 결과 카드도 표시한다. WSC 타임라인은 여전히 마지막 대각부터 시작한다.
- 현재 칸 강조와 실시간 A/B 숫자: 대각에서 A=1f, 뒤 입력 때 A 고정·B=0f 시작. 프레임이 증가할 때 모바일 스크롤이 현재 칸을 따라간다. 2026-09-19 수정: 15f를 넘으면 현재 칸 강조를 없애고, 이후 입력도 15f 칸에 넣지 않는다. 정확한 A/B 숫자와 판정은 계속 유지한다. 완료·취소·만료 시 진행 강조를 제거한다. RAF는 표시만 담당하며 입력 판정의 시간 환산을 바꾸지 않는다. 동작 줄이기에서도 부드러운 애니메이션 없이 칸·숫자를 표시한다.
- 랜덤 도전은 **10회, N=0~3**으로 축소한다. N+1번째 성공 조건과 중단 재시도 정책은 유지한다.
