# 설계 결정 전문

사용자가 내린 설계 결정의 **정본**이다. 바꾸려면 먼저 사용자에게 묻는다. `AGENTS.md`에는 한두 줄 요약과 번호만 둔다.

- 번호는 **바꾸지 않는다**. 철회된 결정도 번호를 비우지 않고 "(철회)"로 남기며, 새 결정은 끝 번호 다음에 붙인다.
- 제목 줄의 `slug`는 코드 주석이 인용하는 식별자다. 코드(`src/`·`tools/`·`worker/`·`tests/`)는 반드시 `결정 N(slug)` 형식으로 인용하고, `tests/docs.test.cjs`가 번호와 slug가 이 파일과 맞는지 검사한다. 번호만 쓴 인용(`결정 29`)은 테스트가 거부한다.
- 결정 본문에는 **무엇을 왜** 정했는지만 둔다. 함수 이름·구조는 `CODE_MAP.md`, 경위는 기능 브리핑(`GIWONCHO.md` 등)이 정본이다.
- 워커 스키마·재배포가 필요한 결정의 배포 순서는 `worker/README.md`의 "배포 순서" 한 곳에만 적는다.

## 1. wave-input — 웨이브 입력 (6N23·623)

2026-09-22 사용자 실게임 확인: 시작 6 다음 중립을 생략한 `623`도 웨이브 입력으로 허용한다. 공통 선행 입력을 쓰는 일반 초풍·나락·웨캔기어에도 적용한다. `6N23`과 `623`은 같은 웨이브·점수 경로를 쓰며 생략한 중립 구간은 0으로 표시한다. 초풍의 동일 슬롯 저스트와 별도 무족초 `6N3+RP`(결정 27)는 유지한다. 웨이브 표기는 `6N23 6 N 6N23 6 N …`. 3 직후 6은 후딜레이 캔슬용이고 다음 대시는 별도의 시작 6이 필요하다. 캔슬 6 없이 다음 6N23이 오면 "캔슬 6 누락", 캔슬 6을 시작 6으로 겸용하면 "시작 6 누락".

## 2. ewgf-judge — 초풍 판정 (60Hz 공통 격자)

초풍(2026-09-18 사용자 변경): 브라우저 공통 60Hz 격자에 각 입력 시각을 `floor(t/(1000/60)+0.5)`로 반올림해 대각·RP가 같은 칸일 때만 성공. 원점은 performance.timeOrigin, 화면 주사율과 무관. 간격 반올림과 구별한다. 0.5/0.7/0.9f 선택 UI 제거. 옛 store.window/Worker win은 저장·통신 호환용으로만 유지하며 새 초풍 판정에는 쓰지 않는다. 기존 기록은 유지, 순위의 판정 폭 열은 제거. 사범 피부 업적은 기존 진행 유지 + 동일 프레임 성공 중 원시 간격 ±8ms 이내를 센다.

## 8. sound — 소리

소리(2026-09-12): BGM은 첫 키·클릭 뒤 재생, 효과음은 완료된 크라우치 대시·초풍 성공 및 사용자 추가 요청(2026-09-18)의 통발·나락·웨캔기어 기술 성공 및 실제 백대시 출력에 재생한다(2026-09-18 정리 음원 교체·백대시 추가). 피격음 원본의 강한 타격음이 정리본에서는 약120ms 뒤에 시작하므로 SFX_START.hit=0.12로 저레벨 앞부분을 건너뛴다(원본 파일 유지, 2026-09-18 디코딩 파형 확인). 첫 사용자 입력에서 모든 효과음 풀을 미리 불러온다. 피격음은 사거리·타입이 맞는 더미의 피격 반응 시작(명중 판정 후 기술별 160~200ms, 사이트 연출 기준)에 1회만 재생한다. 2026-09-18 사용자 조정: 통발·기상어퍼 음량은 효과음 설정의 80%로 재생하며 볼륨 변경 후에도 유지한다. 기술 소리는 헛쳐도 재생하지만 피격음은 헛침·중복 명중에는 없다. 소리는 연출 끄기·동작 줄이기와 독립이고 효과음 볼륨/음소거를 따른다. 설정은 켜기/끄기 + 배경음·효과음 볼륨 분리. 부트 시 Audio를 만들지 않는다(테스트·og 생성이 미디어를 안 건드리게). 배경음만 끄는 토글 `store.bgm`이 따로 있고(2026-09-14, 설정 창 + 헤더 스피커 버튼 `#bgmBtn`), 헤더 버튼은 `sound && bgm` 효과 상태를 보여준다. 배경음을 켤 때 마스터 소리도 켜며 효과음 볼륨은 유지한다. 2026-09-19 사용자 요청: `bgm/` 전용 폴더의 MP3를 랜덤 순환한다. 현재 bgm.mp3 + 사용자 지정 High Rollers Club + DUOMO DI SIRIO + Mishima DOJO + Infinite Azure - Round 1 (Moonsiders 1st)이며 Moonlit Wilderness는 제외했다. 2026-09-21부터 Pages Actions의 `tools/build-site.js`가 `bgm/playlist.json`을 자동 생성하고 앱은 같은 출처에서 읽는다(외부 API 추가 없음). 로컬 미리보기 목록은 `node tools/update-bgm.js`로 갱신한다. 하위 폴더·숨김 파일 제외, 파일명을 곡명으로 표시한다. 빈 폴더는 무음, 한 곡은 반복한다. 2026-09-20 사용자 요청: 접속마다 전체 재생목록을 셔플하고 순서대로 한 번씩 재생한다. 곡 종료·다음 곡 버튼은 같은 대기열을 소비하며, 한 바퀴가 끝나면 다시 셔플하되 직전 곡과 연속되지 않게 한다. store.bgmLast에 파일 경로를 저장해 재접속 첫 곡도 직전 곡을 피한다. 상단 음소거/재생·일시정지/다음 곡/현재 곡을 한 그룹으로 묶는다. 일시정지는 snd.paused 세션 상태로 유지하며 음소거·효과음과 분리, 다음 곡도 일시정지·음소거를 해제하지 않는다. 기존 Web Lock 단일 창 재생과 백그라운드 중지는 유지한다. 결정 8 음량 보정 추가(2026-09-19): 기본 bgm/bgm.mp3의 -19.17 LUFS를 기준으로 BGM_GAIN 경로별 재생 게인을 적용한다. ## 17. backdash — 백대시·bd10

백대시 연습·백대시 10초(bd10, 2026-09-13, 사용자 요청): 한국식 백대시 `414 N 414 N …`(4 N 4로 백대시, 1(↙)로 경직 캔슬, 1에서 4로 바로 굴려 다음 4 N 4). 판정 머신 `bd`는 `cd`와 **완전히 독립**(방향 입력만 봄 — 4·N·1이 세트, 2/8/7/9는 횡 캔슬, 3은 앉기 캔슬, 6은 실수 — 버튼과 `cd`는 읽지도 쓰지도 않음)이고 자유 연습과 bd10에서만 돈다(`bdActive`). 자유 연습에서는 첫 1 캔슬 전까지 문구를 내지 않는다(`bd.engaged`, b,N,b만으로는 위치 조정). 1 뒤 중립(1→N→4)은 실수, 2/8 캔슬은 횡(가드 풀림) 실수로 표시하되 거리는 인정. 4 N 4를 묶는 규칙은 연출(`tapDetect`)과 같다(두 번째 4가 첫 4로부터 250ms 안). 점수는 10초 동안 물러난 거리(m), tie = 매우 빠름 세트 수, 워커 `BOARDS.bd10`. 등급 이름은 Perfect/Great/Good을 쓰지 않는다.

**실측 모델(2026-10-02 사용자 결정 B안, 근거·출처는 `BACKDASH.md`).** 처음(2026-09-13)의 `BD`{MIN_F 6 · MOVE_F 10 · 거리 = min(h,10)/10 m · TIERS 3.5/3.0/2.2 m/s}는 사용자 체감 가정값이었고 다음으로 바뀌었다.

- 세트 속도 = 거리 × 60 ÷ (캔슬 프레임 h + 손 입력 프레임 c). c = 1을 누른 뒤 다음 백대시가 나올 때까지. 이 공식을 가장 크게 만드는 h가 그 손의 최적 캔슬(`bdBestH`)이고, 손 3~12f에서는 12~13f다. 권장 캔슬 창(`CANCEL_A~B`)은 2026-10-04 사용자 요청으로 11~13f로 조정했다. 1을 누른 순간의 피드백은 이 창으로, 세트 코치는 그 세트의 c로 계산한 최적과 비교한다.
- 등급은 손 속도 기준: 매우 빠름·빠름·보통 = 손 7·10·16f로 최적 캔슬했을 때의 속도 이상(`BD.TIERS`→`BD_TIER_MPS`, 1.78/1.55/1.23 m/s).
- `RECOVER_F` 26(캔슬 없는 백대시 경직, 출력 기준)은 실측 총 길이 약 25f와 맞아 유지. 그동안 뒤로만 못 간다(백대시·뒤 걷기 없음, 나머지는 전부 가능). 앉기·횡 방향이 지운다. 판정과 무관하게 **모든 모드의 연출**에 적용되며(`bdRec`), 경직 중엔 캐릭터가 백대시 자세를 유지하고 큰 텍스트는 띄우지 않는다. 캔슬 없이 4를 뗀 백대시의 풀 거리는 경직 안에 앉기·횡이 오면 그 시점까지의 거리로 깎인다(떼고-앉기 반복으로 거리를 불릴 수 없음). `LINK_MAX_F` 60 유지.
- 캐릭터 백대시 연출도 같은 곡선으로 움직인다(`bdEase`, 결정 9: 연출은 판정을 바꾸지 않고 판정과 같은 모양을 보여 줄 뿐).
- bd10에는 기원초 연습처럼 하단 프레임 타임라인과 세트 평가 패널을 둔다(0f = 백대시 출력, 칸 채움 = 그때까지의 거리, "최적 캔슬" 구간과 그 손의 최적 프레임, 감속 구간(14~17f, 거의 멈춰 끌어도 이득 없음), 다음 백대시, 축 아래 1 홀드·4 N 4 띠와 목표(2f·4f, 합 `HAND_F` 6f), 공식 계산식, 세션 통계). 새 모드는 만들지 않았다.

## 25. wsc — 웨캔기어

웨캔기어(2026-09-18 사용자 승인·후속 UI 변경): 전용 `wsc` 모드에서 단계 버튼 없이 전체 입력을 평가하며 플레이 아래 패널에 A/B 피드백을 따로 표시한다. 선행 웨이브는 `6N23` 한 덩어리, 프레임 표는 마지막 대각을 1f로 시작. 최종 사용자 정정: A는 대각 입력 순간을 1f로 포함하므로 실제 7/8/9f 경과 → A=8/9/10, B=1/1~2/1~3f. A는 60Hz 경과 반올림 +1, B는 뒤 입력 순간 0f 기준 경과 반올림(유지). A는 대각 유지·중립·앞 입력 1회, B는 뒤 유지·중립만 허용. 뒤+RP 동시 실패. `6N23`·`623` 허용(2026-09-22 사용자 실게임 확인), 다음 완전한 웨이브의 마지막 대각으로 기준 갱신(캔슬·시작 앞은 별도). 세션 통계 하나 + 로컬 랜덤 과제 10회 도전(3초 카운트다운, 매 과제 N=0~3 무작위·중복 허용, 웨이브 N회 후 정확히 N+1번째에 성공, 성공률/최고 연속). 1초 중단·선행 순서 오류는 평가 분모 제외 및 같은 과제 재시도, 웨캔기어로 완료한 버튼 입력은 성공·실패 모두 다음 과제, 모드/방향/포커스/탭 숨김/모달 진입은 진행 시도·도전 취소. 완료 결과는 다음 도전까지 유지, 새로고침은 기록 삭제. 모든 모드가 동일 커맨드 판정·연출을 공유하며 자유 연습에서도 웨캔기어, wsc에서도 초풍·나락·통발 등을 쓸 수 있다. 대각 후보에 뒤 입력이 있으면 웨캔기어 경로가 버튼을 소비하고, 없으면 기존 기술로 판정한다. wsc 모드에서는 기존 기술의 통계·업적 기록도 차단하고 다른 기술 입력은 도전 과제를 소비하지 않는다. 다른 모드의 선행 웨이브는 기존 규칙대로 집계하되 웨캔기어 마무리는 초풍 시도·측정 점수·업적에 포함하지 않는다. 2026-09-19 사용자 추가 요청으로 전용 리더보드를 연결(결정 26), DB 스키마는 그대로. 하단 입력 프레임 이력 복구, 대각 이후 현재 칸 강조·A/B 실시간 숫자·모바일 자동 스크롤(2026-09-19 수정: 1~15f만 표시, 15f 초과 입력·현재 칸 강조는 생략하고 실제 A/B 숫자와 판정은 유지). 자체 기상어퍼(앉기→올려치기→복귀)·팝·일반 더미 반응 및 사용자 제공 기상어퍼 효과음. 도전 횟수만 틀린 경우에도 기술 자체가 성공하면 기술 연출·소리는 나오되 도전은 실패다. 명중 순간 180ms 충격 원·방사선·불꽃(기존 색 토큰)을 표시하며 연출 끄기·동작 줄이기에서는 생략한다. 실패 기술명 단정 금지. 상세 `.agents/docs/WSC_PRACTICE.md` 10·11절.

## 30. giwon — 기원권·기원초

기원권·기원초(2026-09-23 사용자 승인. 이후 2026-09-24·27·28 사용자 요청으로 확장. 구현 경위와 근거는 `.agents/docs/GIWONCHO.md`, 코드 구조는 `CODE_MAP.md`):

**기원권** `↘+RP`는 **모든 모드**에서 기술이다(통발·나락과 같은 `strike` 경로 — 저스트 없음, 초풍 성공률·히스토그램·연속·`session.tries`에 잡히지 않음). 이전에 `no_cd` 실패로 세던 경로라 코치에 "초풍을 노렸다면 6N23이 빠졌습니다"를 함께 낸다. `↘`가 실제로 눌려 있을 때만 기원권이고, RP가 대각보다 먼저 와도 같은 60Hz 칸이면 인정한다. 중립→`↘` 굴림이 앞을 1프레임 스치므로 `f_before_d` 실패는 `↘`가 RP 없이 빠지거나 `GIWON.FAULT_MS`가 지날 때까지 보류한다. `HIT_TYPE`에 없어 더미 격파 30초에서는 언제나 헛침이다.

**기원초**는 기술이 아니라 **링크**이고, 재는 값은 **초풍이 몇 프레임에 발동했는가** 하나다(2026-09-27 인게임 확인). 성공은 `초풍이 GP_TARGET(49f)까지 발동`이며 **커맨드 루트는 보지 않는다**(기존 판정이 초풍으로 인정한 발동이면 된다 — 결정 1·2·27을 재활용하고 링크 쪽에서 새로 정하지 않는다. 2026-09-30 통합 기준으로 `6N23`·`623`·`6N3` 모두 기존 초풍 판정을 따른다). 발동 프레임은 `max(누른 칸, 경직 해제 칸)`이다. 중립·시작 6 위치는 **참고값**으로만 표시하고 판정을 바꾸지 않는다. 결정 27을 유지해 명중 프레임·지상/공중 히트는 재현하지 않고 문구도 "입력 조건 충족"으로만 쓴다.

**프레임 기준**(사용자 인게임 확인): 기원권 입력이 1f, 명중이 `ACTIVE_F`+1, 리커버리가 그 다음 칸부터이므로 처음 행동할 수 있는 = **중립이 들어가는** 칸은 `GP_FREE`=`ACTIVE_F`+`RECOVERY_F`+2 = **48f**이고 목표는 `GP_TARGET`=49f다. `giwonLink.tRec`도 이 칸에서 역산해 그려진 칸과 판정이 어긋나지 않게 한다. 경직의 끝은 **60Hz 칸 단위**로 본다(2026-09-28: 원시 시각으로 비교하던 탓에 48f 칸 앞쪽 절반의 중립이 버려져 49f에 넣어야 성공하는 것처럼 보였다). 시작 6 선입력 창은 **40~46f**이고 **47f는 선입력 창이 아니다**(2026-09-28 사용자 확인).

**경직 중 동작**(모든 모드): `RECOVERY_F` 동안 걷기·대시·기술이 하나도 나가지 않는다. 버튼은 해제 직전 `BUFFER_F` 안에 눌린 **하나만** 버퍼되고(한 칸짜리라 마지막 입력이 덮어쓴다) 판정 시각은 **실제 누른 시각**이라 대각+RP 같은 칸 관계가 남는다. 방향 중 경직을 넘는 것은 **시작 6 하나**이고 중립부터는 경직이 끝난 뒤에 들어가야 한다. 버려진 버튼은 연습 모드 평가 줄에만 알리고 실패·통계로 세지 않는다.

**연출**(전부 연출 전용 — 판정·좌표·통계에 영향 없음, `store.fx===0`·동작 줄이기에서 생략): 더미는 반격하지 않고 제자리에서 배잡기 경직에 들어갔다가 후속타나 `CRUMPLE_MS` 뒤에 날아간다. 같은 더미에 기원권을 **두 번** 맞히는 것은 연결 실패라 약하게 날리고, 새 시도가 아니므로 연습 타임라인을 다시 돌리지 않는다. 연결 결과로 더미 반응이 갈린다(성공은 크게, 늦은 초풍은 픽 쓰러짐). 성공하면 캐릭터 위 팝이 "초풍!"이 아니라 **기원초!** 이고(연속 2회부터는 기존 N초 표기), 합성 팡파르와 폭죽·색종이가 나온다(음원 파일 없음, 소리는 효과음 볼륨·음소거만 따른다). 더미 발밑 경직 게이지는(2026-09-29: 머리 위에서는 팝 글자에 가려 발밑으로 옮김) **경직이 끝나는 시점 하나만** 알리고(선입력 구간은 그리지 않는다) 한 번 붙은 위치를 지킨다. 카운터 줌은 3D 카메라와 2D 레이어를 같은 배율로 키운다. 모션은 어퍼컷이 아니라 **라이트 훅**이다. 효과음은 사용자 제공 2종(`sfx/giwon.mp3` 기술음·`sfx/giwon-ch.mp3` 카운터음, `SFX_GAIN 0.75`).

**기원초 연습 모드 `giwon`**(2026-09-24, 모드 탭 3번째): 측정·카운트다운 없는 무제한 연습이고 탭 이름은 기술이 아니라 링크를 따라 **기원초 연습**(en `d/f+2 → EWGF link`, ja `3+2 → 最風連係`)이다. 프레임 표는 판정이 없는 두 구간(발동·경직)만 한 칸으로 묶어 **가로 스크롤 없이** 들어가고, 묶은 칸 안에도 프레임 눈금과 진행 채움이 흐른다. 축 위에는 구간 이름이 붙는다 — 회색 `선입력`(40~46f) · 금색 `중립`(48f) · 주홍 `공격`(49f). 더미는 한 개만 `GP_DUMMY_PX` 앞에 서고 쓰러지면 `GP_DUMMY_MS` 뒤에 같은 자리로 돌아온다. 플레이와 타임라인이 한 화면에 오도록 배치한다. 세션 통계는 새로고침하면 사라지고, 이어지지 않은 기원권은 "중단"으로 남겨 분모에서 뺀다. 웨캔기어와 달리 기존 초풍 통계·업적을 막지 않는다(후속타가 실제 초풍이므로). 2026-09-28 사용자 요청으로 **로컬 10회 도전**을 추가했다(3초 카운트다운 → 평가된 시도 10회 → 성공률·최고 연속). 중단은 분모에서 빠지고 모드를 벗어나면 취소된다. 완주 결과의 순위는 결정 31.

`GIWON`{ACTIVE_F 14 · RECOVERY_F 32 · GROUND_F 13 · BUFFER_F 8 · FAULT_MS 450 · CRUMPLE_MS 900 · LINK_MS 1200}과 `GIWON_ZOOM`{PEAK 1.12 · IN_MS 60 · OUT_MS 470}은 결정 17의 `BD`와 같은 **실게임 미확인 가정값**이며 문구·테스트가 상수를 읽으므로 숫자만 바꾸면 된다. 서버·DB 변경 없음.

## 31. giwon-board — 기원초 리더보드

기원초 리더보드(2026-09-30 사용자 요청 "웨캔기어식 10회 순위"): 결정 26과 같은 방식. `giwon` 전용 보드에 기원초 연습의 로컬 10회 도전을 **끝까지 마친** 결과만 자동 등록한다. score=성공 횟수(0~10 정수), tie=최고 연속 성공(0~10 정수), 동점은 공동 순위. 중단·취소·일반 연습은 등록하지 않는다. `gp.challenge.result`를 따로 두어 `trial.result`·로컬 측정 기록·업적·공유 카드에는 섞지 않는다. 실패 시 재시도, 닉네임 미설정 시 설정 후 등록, 본인 기록 삭제 지원. 워커 `BOARDS.giwon`(`wsc`와 같은 `CHALLENGE_10` 명세라 정수·일치 검증을 공유), 관리자 도구에 추가. 기존 `scores` 테이블이라 마이그레이션은 없고 **워커 재배포는 사용자 작업이며 사이트 푸시보다 먼저** 한다(반대면 재배포 전까지 등록이 400으로 거부되고 실패 문구가 뜬다). 10점 만점이라 상위권 동점이 많아질 수 있다는 한계는 사용자에게 설명했다.
