# 무족초 설계

2026-09-22 사용자 실게임 확인 반영: 웨이브·일반 초풍·나락·WSC는 `6N23`과 중립 생략 `623`을 모두 허용한다. `cd.omittedNeutral`은 실패 사유가 아닌 입력 경로 표시용이며 캔슬/해제까지 유지하고 다음 시작 앞에서 초기화한다. 무족초 `6N3+RP`의 독립 경로와 저스트 조건은 유지한다.

작성: 2026-09-20. 상태: 설계 후 사용자 구현 지시로 구현 완료. 1~7절은 최초 설계이며, 구현 시 구체화한 동작·검증은 8절을 우선한다.

## 1. 사용자 승인 범위와 이번 제안

사용자는 조사 결과의 `6 N 3+RP` 무족초 인정, 무족초 성공과 최속 성공 구분, 앞·중립·RP 프레임 피드백, 기존 `623+RP`와의 입력 경로 구분을 승인하고 설계를 요청했다. 이어 최신 리베이스 후 작업 진행을 지시하여 초기 지원 범위로 구현했다.

아래의 초기 적용 범위·통계 연결·후보 처리 방식은 구현 제안이다. 실제 게임에서 확인하지 않은 허용 시간이나 대시/웨이브 연결을 승인된 게임 규칙으로 간주하지 않는다.

## 2. 커맨드와 최속 기준

- 방향은 상대 기준: `f → n → df + RP` = 오른쪽을 볼 때 `6 N 3+RP`, 왼쪽을 볼 때 `4 N 1+RP`.
- 무족초 경로에는 아래 단독 `d`가 없다. `6N23`은 기존 일반 경로, `623`은 중립 생략 일반 경로다.
- 입력 종류와 성공 여부는 별도 정보다. `6N3` 뒤 RP가 늦으면 무족초 입력 경로의 저스트 실패이며, 성공한 무족초로 집계하지 않는다.
- 초풍 성공: 기존 `frameSlot(t) = floor(t / (1000/60) + 0.5)`에서 대각과 RP의 슬롯이 같다. 원점·시각 소스는 기존 정책 그대로다.
- 앞 홀드 `fFrames = frameSlot(tN) - frameSlot(tF)`.
- 중립 홀드 `nFrames = frameSlot(tDF) - frameSlot(tN)`.
- RP 차이 `rpFrames = frameSlot(tRP) - frameSlot(tDF)`.
- 유효한 무족초 경로는 `fFrames >= 1 && nFrames >= 1`. 0칸을 임의로 1f로 올리지 않는다. 브라우저에서 관측했더라도 공통 격자에 앞/중립 칸이 없으면 입력 부족으로 안내한다.
- 최속 무족초: 유효 경로 + `rpFrames === 0` + `fFrames === 1 && nFrames === 1`.
- 원시 ms와 슬롯 차이를 함께 보존한다. 프레임 수를 `round((t2-t1)/FRAME)`로 계산하지 않는다.
- 대각과 RP는 같은 칸이면 이벤트 도착 순서와 원시 시간의 선후에 상관없이 같은 결과다. 이 원칙은 앞/중립 각 1칸 확인과 별개다.

| 입력 예 | 판정 | 안내 |
|---|---|---|
| 앞 1f, N 1f, RP 0f | 최속 무족초 | 앞·중립 각각 1f |
| 앞 3f, N 2f, RP 0f | 무족초 | 앞 2f·중립 1f를 줄이면 최속 |
| 앞 1f, N 1f, RP +1f | 저스트 실패 | RP 1f 늦음 |
| 앞 1f, N 1f, RP -1f | 저스트 실패 | RP 1f 빠름 |
| 앞 또는 N 0칸 | 입력 부족 | 앞/중립을 최소 1프레임 유지 |
| `6N23+RP` | 기존 초풍 판정 | 무족초 라벨 없음 |
| `623+RP` | 중립 생략 일반 초풍 | 대각/RP 동일 슬롯이면 성공, 웨이브도 집계 |
| `63+RP` | 순서 오류 | 중립 필요 |

`13f`는 앞 1f + 중립 1f + 기술 발동 11f라는 입력 포함 최속 발동을 뜻한다. 사이트는 명중까지의 실제 13f나 가드 경직 종료 타이밍을 재현하지 않는다. 결과 제목은 `최속 무족초`, 설명은 `13f 발동에 필요한 입력 조건 충족`으로 구분한다. 사이트의 기존 명중 연출 지연을 13f로 바꾸지 않는다.

## 3. 첫 구현 범위 제안

별도 측정 모드나 순위 보드는 추가하지 않고 기존 연습에서 입력을 인식하고 결과 카드·구간 표시·로그를 확장한다. 별도 모드 없이 일반 초풍과 번갈아 연습할 수 있게 한다.

첫 범위는 독립적으로 시작한 `6N3+RP`다. 시작 6이 기존 `tapDetect`에서 대시로 판정되었거나, 웨이브 캔슬·재시작 과정에서 온 경우에는 무족초 후보를 만들지 않는다. 기존 명령이 종료된 뒤 새로 시작하는 입력은 새 후보가 될 수 있으나, 대시 감지가 붙으면 위 제한을 우선한다. 시간만 지난 것을 명령 종료로 간주하는 조건은 기존 리셋/타임아웃과 일치시킨다.

이 제한은 첫 구현의 지원 범위이며 실제 게임에서 불가능하다는 뜻이 아니다. 제외 경로는 `이 연결의 무족초 판정은 아직 지원하지 않습니다`로 안내하고 실제 기술 실패를 단정하지 않는다. `6N23`·`623` 대시/웨이브 경로는 일반 판정기로 처리한다.

| 모드 | 제안 처리 |
|---|---|
| 자유 연습 | 무족초/최속 라벨, 초풍 기존 통계·연속·효과음·더미 반응 재사용 |
| 초풍 20회 | 기존 초풍 1회와 같은 성공·실패 집계, 최속 추가 점수 없음 |
| 웨이브 10초 | 기술 출력과 기존 초풍 통계만, 웨이브 수 증가 없음 |
| 웨이브 초풍 | 무족초로 선행 웨이브 수 증가 없음; 기존 과제 부족 안내가 제목보다 우선 |
| 더미 격파 30초 | 성공은 기존 초풍 10점, 늦은 RP의 유효 풍신권은 기존 5점; 아래 생략으로 웨이브 점수는 없음 |
| 백대시 10초 | 기술 출력은 가능, 백대시 거리/머신과 독립 |
| 웨캔기어 | 다른 기술과 같이 연출만, 기존 통계·업적 차단 유지, 도전 과제 소모 없음 |

무족초용 업적·영구 기록·서버 필드·전용 소리·리소스는 추가하지 않는다. 기존 초풍 업적은 기존 규칙으로 반영하며 사범 피부는 동일 슬롯 성공 및 원시 간격 ±8ms 조건을 유지한다. 최속 여부가 추가 업적 보너스를 만들지 않는다.

## 4. 판정 구조 제안

현재 `onDir`의 상태 2에서 `df`는 `fault('n_to_df')`다. `completeCD`는 방향 입력만으로 웨이브 체인, 누적 업적, wave10/rush30 점수, 웨이브 효과음을 처리한다. 그러므로 무족초를 허용하기 위해 상태 2에서 `completeCD`를 부르면 안 된다.

작은 무족초 후보 상태를 추가한다(가칭 `mist`). 후보는 앞·중립·대각 시각, 시작 출처, 대기 중 RP, 만료 시각만 추적한다. `cd.chain`, `lastDF`, `cancelled`를 무족초를 위해 위조하지 않는다.

1. 독립적인 시작 `f`에서 후보 시작 → `n` → `df` 순으로 진행한다.
2. `n → d`면 후보를 버리고 기존 `6N23` 경로에 맡긴다. `f → d`는 무족 후보를 버리고 중립 생략 일반 경로에 맡긴다.
3. 자격 있는 `n → df`는 무족초 후보가 소비하여 기존 `n_to_df` 오류를 억제한다. 웨이브 완료 처리·WSC 대각 후보 생성은 호출하지 않는다.
4. RP가 먼저 도착한 `n` 상태에서는 기존 즉시 `early_stage`를 잠시 보류할 수 있어야 한다. 기존 대시의 통발 자격은 먼저 처리하며 무족초 대기에 빼앗기지 않게 한다.
5. 후보 대각과 RP가 모이면 `classify`/`attempt`에 명시적 문맥을 전달해 기존 초풍 결과 처리를 재사용한다. `t-off`와 `cd.lastDF`를 혼동하지 않도록 대각 시각을 후보에서 제공한다.
6. 결과 레코드에 선택 필드 `inputRoute`, `fFrames`, `nFrames`, `fastest`를 제안한다. 경로는 일반/중립 생략/무족으로 구별한다. `kind`는 기존 성공·실패 종류를 유지한다. 새 필드가 없는 과거 기록을 무족 또는 최속으로 추정하지 않는다.
7. `endCommand`, `resetInput`, 모드/방향 전환, 포커스 상실, 탭 숨김, 모달, 측정 시작/종료에서 후보와 보류 RP를 초기화한다. 취소된 후보가 나중에 결과를 내면 안 된다.

보류 RP 뒤에 `d`가 들어오면 무족초 자격은 사라지고, 보류했던 입력은 기존 조기 입력 결과로 정확히 한 번 종료한다. 이를 미래의 일반 초풍에 붙이지 않는다. RP 후 대각이 오지 않고 기한 만료 시에는 대각 누락 결과 1회만 낸다. RP 없이 후보만 만료되면 시도 수를 올리지 않는다. 비RP 버튼은 무족초 시도로 세지 않고 후보를 취소하며, 기존 기술에 유효한 입력이면 원래 경로에 전달한다. `6N3+RK` 나락과 `6N3` 이후 WSC는 이번 확장 대상이 아니다.

대각 도착 전 보류 RP는 기존 120ms를 재사용하는 구현안이며, 순서 복원을 위한 대기 상한이다. 성공 허용 폭을 ±120ms로 넓히는 것이 아니다. 방향 후보 타임아웃은 기존 앞/중립 250ms, 대각 450ms를 임시 사이트 정책으로 재사용하는 안이다. 실제 게임의 무족 허용 시간으로 문구에 표시하지 않는다. 경계는 입력 처리 시각에도 검사하여 렌더 주사율에 의존하지 않도록 한다.

키보드·터치는 대각을 만드는 두 방향 이벤트가 순차 도착한다. 같은 슬롯 안의 순간적인 `d`/`f`를 별도의 유지 프레임으로 볼지에 따라 경로가 달라질 수 있다. 구현 전 이 부분을 작은 입력 재현 테스트로 확인해야 한다. 제안은 무족 후보에서만 최종 대각과 같은 슬롯에 발생한 중간 방향을 보류하여 같은 물리 입력의 순서 차이를 흡수하는 것이다. 이때 기존 `onDir`의 웨이브 완료·통발·WSC를 먼저 실행한 뒤 되돌리는 방식은 금지한다. 후보가 소유한 이벤트를 확정 후 한 경로에만 전달하고, 이전 슬롯을 실제로 차지한 `d`는 일반 초풍으로 구별한다. 기존 `623` 판정 정책을 전체적으로 슬롯 집계 방식으로 바꾸지 않는다. 이 이벤트 중재가 기존 동작과 충돌하면 구현 전에 범위를 다시 검토한다.

무족 후보 처리와 `wscDir`의 호출 순서를 검토한다. 새 경로만 억제하고 완전한 `6N23` 및 이미 뒤 입력을 받은 WSC 후보의 버튼 우선권은 보존한다. `bd`는 읽거나 쓰지 않는다. 효과음·결과·시도·순위 제출은 동일 버튼에 중복 실행하지 않는다.

## 5. 화면과 다국어

기존 결과 카드와 마지막 구간 막대를 재사용하고 무족 경로일 때 `앞 / 중립 / ↘+RP`를 표시한다. 없는 아래 구간은 0f 막대 대신 생략한다. 입력 프레임 이력은 실제 입력을 그대로 남긴다.

예시:

```text
무족초!
앞 3f · 중립 2f · RP 같은 프레임
최속까지: 앞 2f, 중립 1f 줄이기

최속 무족초!
앞 1f · 중립 1f · RP 같은 프레임
13f 발동에 필요한 입력 조건 충족

RP가 1f 늦었습니다
앞 1f · 중립 1f · RP +1f
↘와 RP를 같은 프레임에 입력하세요
```

로그에 입력 경로와 최속 여부를 표시한다. 일반 초풍의 기존 대초/연속 표시와 혼동하지 않도록 무족초에는 대초 라벨을 붙이지 않는다. 좁은 화면은 숫자 행을 줄바꿈하며 새 모달은 만들지 않는다.

예정 I18N 키 묶음: `mist.title`, `mist.fastest`, `mist.frames`, `mist.improve`, `mist.input13`, `mist.missingFrame`, `mist.unsupported`, `route.standard`, `route.noNeutral`, `route.mist`. 실제 추가 시 ko/en/ja 같은 키를 채우고 동적 결과는 번역 키 배열/클로저로 보존한다. 영어 무족초는 `Mist Step EWGF`, 일본어는 `無足最風`, 최속은 각각 `Fastest Mist Step EWGF`, `最速無足最風`를 제안한다. 공식 캐릭터 이름·그림은 사용하지 않는다.

## 6. 미확정 조건과 실게임 확인

현재 상세 프레임 근거에는 구작 자료가 포함된다. 아래를 확인하기 전에는 최신 게임의 정확한 허용 범위나 모든 연결 지원을 주장하지 않는다.

- 앞/중립을 각각 늘려 `6N3+RP`가 성립하는 마지막 프레임 확인. 앞과 중립의 개별 제한인지 합산 제한인지도 구분.
- `6N6N3+RP` 대시 연결, 웨이브 취소 후 `6N3+RP` 연결의 실제 출력 확인.
- 입력 이력에서 앞 1f/N 1f/대각+RP 동시와 2f 홀드를 비교. 최속 입력 성공과 경직 직후 딜캐 성공을 각각 관찰.
- RP 선행/대각 선행, 중립·대각의 경계에서 게임 입력 이력과 출력 비교.

관측 기록에는 게임 버전, 방향, 입력 이력의 프레임 수, 실제 기술 출력, 시작 상황(정지/대시/웨이브/경직 직후)을 함께 남긴다. 확인 결과가 사이트 임시 정책과 다르면 먼저 설계를 갱신한다. `20f` 등 다른 연습기의 수치를 게임 규칙으로 복사하지 않는다.
