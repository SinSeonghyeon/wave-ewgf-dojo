# 보조 키 설정 기능 인수인계

## 기준

- 브랜치: `SinSeonghyeon/workspace03`
- 기능 최종 커밋: `20593d263e012128d5ac2da7f10a0057f3139897`
- 한 줄 목적: 키보드의 방향·버튼 동작마다 기존 기본 키 외에 보조 키 하나를 추가한다.
- 이 문서만 담는 후속 커밋까지 브랜치 전체를 합류 대상으로 삼는다.

## 합류 순서와 의존성

- 먼저 합류해야 하는 의존 브랜치: 없음.
- `feature/notices`에는 다른 기능 브랜치와 순서 무관하게 합류할 수 있다.
- 다만 다른 브랜치가 `index.html`의 설정 UI, `store` 로더, 키보드 이벤트 또는 I18N 사전을 수정했다면 아래 보존 동작을 기준으로 충돌을 해결한다.

## 사용자에게 보이는 변경과 공지

- 설정의 키 설정이 동작별 기본/보조 두 칸으로 표시된다.
- 보조 칸을 누르고 키를 입력해 두 번째 키를 지정할 수 있다.
- 보조 칸에서 Delete 또는 Backspace를 누르면 보조 키가 삭제된다.
- 방향 기본/보조 키를 함께 누른 뒤 하나만 떼어도 다른 키가 눌린 동안 방향이 유지된다.
- 같은 버튼의 기본/보조 키를 함께 눌러도 초풍 판정·통계·측정 횟수는 논리 입력 한 번만 처리한다.
- 공지 필요 여부: 예.

| 언어 | 제목 | 요약 | 항목 |
|---|---|---|---|
| ko | 보조 키 설정 추가 | 방향과 공격 버튼마다 두 번째 키를 지정할 수 있습니다. | 1. 설정의 기본·보조 칸에서 동작별 키를 지정하세요.<br>2. 같은 버튼의 두 키를 함께 눌러도 입력은 한 번만 판정됩니다. |
| en | Alternate key bindings | Assign a second key to every direction and attack button. | 1. Set primary and alternate keys for each action in Settings.<br>2. Pressing both keys for one button is judged as a single input. |
| ja | サブキー設定を追加 | 方向と攻撃ボタンごとに2つ目のキーを設定できます。 | 1. 設定のメイン・サブ欄で各操作のキーを指定できます。<br>2. 同じボタンの2キーを同時に押しても入力は1回だけ判定されます。 |

공지 최종 문자열과 `NOTICES` 항목은 통합 담당자가 같은 배포 묶음의 다른 기능 공지와 합친 뒤 `index.html`의 ko/en/ja I18N에 동일 키로 추가한다. 이 기능 브랜치에는 공지 시스템 코드나 `NOTICES` 변경을 넣지 않았다.

## 충돌 예상 지점

- `index.html`
  - CSS: `.keys`, `.key`, `.key-pair`, `.key-bind`
  - 설정 마크업: `set.keys`, `set.keyRemove`
  - 저장 형식과 로더: `store.altKeys`, `validKey`, 저장 키 중복 검사
  - I18N: `set.keys`, `set.keyAdd`, `set.keyPrimary`, `set.keyAlt`, `set.keyRemove`
  - 입력: `kbVector`, `mappedCodes`, `buttonForCode`, `buttonHeld`, `keydown`/`keyup`
  - UI: `renderKeys`
- `tests/dojo.test.cjs`: 저장값 검증과 기본/보조 동시 입력 회귀 테스트.
- `tests/smoke-chrome.js`: 설정에서 보조 키 등록·저장·새로고침 복원·실사용 검사.
- `.agents/docs/PLAN.md`, `.agents/docs/CODE_MAP.md`: 다른 기능 브랜치도 자주 수정하므로 내용 단위로 병합한다.

## 병합 시 반드시 보존할 동작

1. 기존 `store.keys`만 있는 저장값은 그대로 동작하고, 누락된 `altKeys`는 빈 값으로 초기화한다.
2. 기본/보조를 포함한 모든 사용자 지정 키는 서로 중복될 수 없고 방향키와도 충돌할 수 없다.
3. 보조 키 삭제는 보조 슬롯에서만 Delete/Backspace로 가능하며 기본 키는 비워지지 않는다.
4. 같은 방향의 기본/보조 키 중 하나를 떼어도 다른 키가 눌려 있으면 중립 입력을 만들지 않는다.
5. 같은 버튼의 기본/보조 키 중 하나가 이미 눌려 있으면 다른 키의 `keydown`은 `onButton`을 다시 호출하지 않는다. 두 키를 모두 뗀 뒤에만 다음 버튼 입력이 발생한다.
6. 키 이벤트의 `timeStamp`, 모달 중 입력 차단, `resetInput`, 방향키 상시 지원과 기존 판정 상태 머신은 그대로 유지한다.
7. 새 사용자 문자열은 ko/en/ja에 같은 키로 존재해야 한다.

## 테스트 결과

- `node --test tests/dojo.test.cjs tests/board.test.cjs`: 통과, 94/94.
- `node tests/smoke-chrome.js`: 재실행 통과, JS 오류 0건. 보조 키 O 등록·저장·새로고침 복원·방향 입력을 포함한 전체 시나리오 통과.
- 첫 스모크 시도는 실패했다. 원인은 부하 상태에서 최초 페이지 부팅이 기본 대기 1.5초 안에 끝나지 않아 닉네임 게이트 초기 DOM이 빈 상태로 캡처된 타이밍 문제였다. 이후 기능 시나리오는 끝까지 실행됐고 보조 키 검사도 통과했다. 최초 대기만 임시로 3초로 늘린 재실행은 전체 통과했으며, 임시 포트·프로필·대기 변경은 모두 원복했다.
- 고정 CDP 포트 9333이 다른 작업공간 Chrome에서 사용 중이어서 테스트 실행에는 임시 포트 9353과 고유 프로필을 사용했다. 기존 프로세스는 건드리지 않았고 이 변경도 원복했다.
- `git diff --check`: 통과. 줄 끝 LF→CRLF 안내만 있으며 공백 오류는 없다.

## 알려진 실패·미완료

- 기능 미완료 없음.
- Chrome 스모크의 최초 부팅 검사는 머신 부하가 큰 경우 기본 1.5초 대기에서 간헐적으로 실패할 수 있다. 기능 실패가 아니며 3초 대기 재실행은 통과했다.
- 테스트 드라이버가 고정 포트 9333과 고정 프로필을 쓰므로 다른 작업공간의 동시 스모크와 충돌할 수 있다.

## 합류 후 브라우저 수동 확인

1. 설정을 열어 8개 동작 각각에 기본/보조 두 칸이 보이는지 확인한다.
2. 방향 보조 키를 등록하고 설정을 닫아 실제 방향 입력이 표시되는지 확인한다.
3. 새로고침 후 보조 키가 유지되는지 확인한다.
4. 같은 방향의 기본/보조 키를 함께 누르고 하나만 떼었을 때 방향이 유지되는지 확인한다.
5. 2(RP)에 보조 키를 등록하고 6N23 직후 기본/보조 키를 함께 눌러 초풍 시도와 측정 횟수가 한 번만 증가하는지 확인한다.
6. 보조 슬롯에서 Delete 또는 Backspace로 키를 지우고 새로고침 후에도 비어 있는지 확인한다.
7. 중복 키와 방향키 지정이 거부되는지 확인한다.
8. ko/en/ja 전환 시 키 설정 안내와 기본/보조 레이블이 모두 번역되는지 확인한다.
