## 기준

- 브랜치: `SinSeonghyeon/workspace01`
- 구현 기준 커밋: `54e5194bef29c93fcfad69dfa48ca11d3aa0217c` (`origin/main`이던 시점에 fast-forward한 기준)
- 준비 시점 원격 브랜치 tip: `origin/SinSeonghyeon/workspace01` = `02b05b3770f9ee45c8692ef8015a132b79ef703c`
- 준비 시점 최신 `origin/main`: `3f05c1550325ca8c111d7186ed7d5ed3ed1e1c62`로 구현 기준보다 1커밋 앞섬
- 기능 최종 커밋: 아직 미커밋. 사용자가 아래 8개 파일을 명시해 커밋·푸시한 뒤, 통합 담당자는 가져온 원격 브랜치 tip과 이 문서가 함께 있는지 반드시 재검증한다.
- 한 줄 목적: 종전 방향 버튼 140%의 실제 크기를 새 100% 기준으로 삼고 상한을 300%까지 늘리되, 기본 100%만 좁은 화면에서 자동 축소한다.

이 문서는 예전 대댓글 작업 인수인계를 대체한다. 대댓글 기능은 이미 `main`에 합류되어 이번 브랜치의 새 합류 범위가 아니다.

- 통합 브랜치는 최신 `origin/main`(`3f05c15` 이상)에서 시작한다.

- Worker, D1, 도메인, 비밀값, 외부 서비스 선행 작업은 없다.

## 사용자에게 보이는 변경과 제외 범위

- 설정의 방향 버튼 크기 기본 표시는 계속 `100%`다.
- 새 `100%`의 실제 버튼 크기는 종전 `140%`와 같다.
- 단, 기본 100%가 공격 버튼 앞 공간을 넘는 좁은 화면에서는 세 방향 버튼이 모두 노출되도록 자동 축소한다.
- 크기 슬라이더는 `70~300%`, 5% 단위이며 선택값을 브라우저에 저장한다.
- 종전 76px 내부 상한을 제거해 새 `300%`까지 실제 크기가 비례해서 커진다.
- 기존 저장값 숫자는 그대로 읽는다. 예를 들어 저장된 `100`은 새 기준 100%로 표시되며 실제 크기가 종전보다 커진다.
- 공격 버튼 크기·위치, 방향 버튼 세로 위치, 터치 판정 경로, 키보드·게임패드, 통계·순위·Worker는 바꾸지 않는다.
- 방향 버튼 가로 위치는 공격 버튼 앞 공간이 아니라 오버레이 내부의 가능한 범위를 사용하므로, 겹치는 사용자 지정 크기에서도 슬라이더가 동작한다.
- 큰 크기는 사용자 선택값을 강제 축소하지 않으므로 좁은 화면에서 공격 버튼 또는 화면 밖과 겹칠 수 있다는 기존 결정을 유지한다.

## 병합 시 반드시 보존할 동작

1. `store.touchSize` 기본값과 정적 슬라이더 표시값은 `100`이다.
2. 새 100%는 기존 반응형 base에 `1.4`를 곱한 종전 140%를 기준으로 하되, 공격 버튼 앞 공간을 넘으면 기본값만 자동 축소한다.
3. 저장 가능한 범위는 정수 `70~300`, 5% 단위다. 문자열·범위 밖·5% 단위가 아닌 값은 기본 100으로 폴백한다.
4. 300%가 종전 76px 상한에 막히지 않고 새 기준의 3배로 반영된다. 스모크의 320px 기준 개별 버튼은 185px이다.
5. `touchX`는 공격 버튼 경계와 무관하게 오버레이 안의 가능한 폭을 쓰고, `touchY`, 독립 ←·↓·→ 멀티터치, ↓+좌/우 대각선, 2P 반전, 모달·blur 초기화 동작을 유지한다.
6. 터치 방향은 `recomputeDir`, 공격 버튼은 `onButton`을 사용하며 판정 상태 머신·통계·순위를 바꾸지 않는다.
7. 100% 이외의 큰 값에는 가용 폭 강제 축소를 넣지 않는다. 좁은 화면 겹침은 허용된 사용자 선택 결과다.
8. 새 사용자 문자열은 없지만 공지를 추가한다면 ko/en/ja 키를 같은 구조로 추가한다.

## 합류 후 브라우저 수동 확인

1. 모바일 또는 설정에서 터치 컨트롤을 강제로 켜고 방향 버튼 크기가 `100%`로 표시되는지 확인한다.
2. 공간이 충분하면 새 100%가 종전 140%와 같은 체감 크기이고, 좁은 세로 화면에서는 공격 버튼과 겹치지 않게 줄어드는지 확인한다.
3. 슬라이더가 70~300%, 5% 단위로 움직이고 새로고침 후 선택값이 유지되는지 확인한다.
4. 140% 등 오버레이 안에 들어가는 사용자 크기에서 가로 위치가 움직이고, 300%는 자동 축소되지 않아 좁은 화면에서 겹침·화면 밖 배치가 허용되는지 확인한다.
5. `→, N, ↓, ↘+2`를 터치해 초풍으로 판정되는지 확인한다.
6. 2P에서 좌우가 뒤집히고 설정/공지/결과 모달 중 입력이 통과하지 않는지 확인한다.
7. 데스크톱 fine pointer의 자동 모드에서는 터치 UI가 숨겨지는지 확인한다.
