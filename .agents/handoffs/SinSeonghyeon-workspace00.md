# 모바일 방향 버튼 개선 인수인계

## 기본 정보

- 브랜치: `SinSeonghyeon/workspace00`
- 인수인계 기준·기능 최종 커밋: `c5dfd879048141c0e2d0286bbdb0934ad808eeaf` (`feat: improve mobile direction controls`)
- 목적: 모바일 원형 방향 패드를 ←·↓·→ 독립 버튼으로 바꾸고 크기·위치를 사용자가 조절할 수 있게 한다.

## 합류 순서와 의존성

- 합류 순서: 공지 기반인 `feature/notices`를 먼저 유지한 뒤 이 브랜치를 합류한다.
- `feature/notices`보다 먼저 추가로 합류해야 하는 의존 브랜치는 없다. 이 브랜치는 `origin/main`의 `89abe35`에서 시작했다.
- 백엔드 의존성은 없다. `BOARD_URL`, Worker, D1 스키마와 순위 계약을 변경하지 않았다.

## 사용자에게 보이는 변경과 공지

- 공지 필요: 예.
- 모바일 방향 입력이 원형 슬라이드 패드에서 ←·↓·→ 버튼으로 바뀐다.
- ↓와 좌우 버튼을 동시에 누르면 ↙/↘가 입력된다.
- 설정에서 방향 버튼 크기(70~140%)와 가로·세로 위치(0~100%)를 조절하고 브라우저에 저장할 수 있다.
- 기본 100%는 320px·390px 화면에서 공격 버튼을 침범하지 않는다. 사용자가 직접 키운 크기는 강제 축소하지 않아 좁은 화면에서 겹칠 수 있다.

## 병합 시 반드시 보존할 동작

1. ←·↓·→는 포인터별로 동시에 눌리며 ↓+좌우가 ↙/↘, 좌+우가 N이 된다.
2. 터치 방향은 `recomputeDir`, 1~4 버튼은 `onButton`을 사용해 키보드·패드와 같은 판정 경로를 유지한다. 판정 상태 머신과 순위 집계는 바꾸지 않는다.
3. 2P에서는 화면 방향을 캐릭터 기준 앞/뒤로 올바르게 뒤집는다.
4. 모달 중 터치 입력을 무시하고 blur/reset에서 보류 포인터와 눌림 표시를 모두 지운다.
5. `touchSize`는 70~140%의 5% 단위, `touchX/touchY`는 0~100%의 5% 단위로 타입·범위를 검증해 저장한다.
6. 기본 크기 100%만 320px·390px에서 공격 버튼 비침범을 보장한다. 사용자가 선택한 확대값은 가용 폭으로 강제 축소하지 않는다.
7. `pointer: coarse` 자동 표시, 강제 켜기/끄기, 터치 정밀도 고지와 ko/en/ja 접근성 라벨을 유지한다.
8. 공지 자동 열기는 측정·결과·다른 모달·보상 연출을 방해하지 않아야 한다.

## 합류 후 브라우저 수동 확인

1. 390px 및 320px 터치 화면에서 기본 100% 방향 버튼이 공격 버튼을 침범하지 않는지 확인한다.
2. 설정에서 크기를 140%로 올렸을 때 좁은 화면에서도 값이 강제 축소되지 않고, 새로고침 후 유지되는지 확인한다.
3. 가로·세로 위치 슬라이더가 즉시 반영되고 새로고침 후 유지되는지 확인한다.
4. →를 눌렀다 떼고 ↓+→+2를 동시에 눌러 초풍으로 판정되는지 확인한다.
5. 2P에서 화면 오른쪽이 뒤(4), 왼쪽이 앞(6)으로 판정되는지 확인한다.
6. 설정·공지·결과 창을 연 상태에서 터치 입력이 뒤로 통과하지 않고, 닫은 뒤 눌림 표시가 남지 않는지 확인한다.
7. 데스크톱 fine pointer에서는 자동 모드의 터치 UI가 숨겨지는지 확인한다.

통합 담당자가 위 내용을 최종 코드·공지·문서에 반영한 뒤 이 파일은 `main` 합류 전에 삭제한다.
